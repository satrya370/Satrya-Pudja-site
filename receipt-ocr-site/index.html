Photograph a receipt. Get back a spreadsheet, not a pile of paper.

Upload a photo of a real receipt — creased, angled, printed on thermal paper that's already fading — and this pipeline reads it with AI vision, checks the math against the printed total, and hands you back a structured Excel workbook or JSON. Built for the receipts people actually have, not clean sample scans.

How it works

Upload the photo

A phone photo of the receipt, plus optionally last time's Excel workbook if you want this one added to it instead of starting fresh.

AI vision reads it

Gemini 2.5 Flash Lite extracts vendor, line items, and totals directly from the image — no manual typing, no template matching against a fixed receipt layout.

The math gets checked

Subtotal, discount, tax, service charge, and rounding are reconciled against the printed total. A mismatch doesn't get hidden — it's flagged on the Validasi sheet instead of silently accepted.

A repair pass fixes malformed output

If the first extraction comes back as broken JSON, GPT-OSS 120B repairs it before anything moves forward — the same fail-closed pattern behind every pipeline on this site.

Duplicates get caught

Each receipt gets a fingerprint from its merchant, date, receipt number, and total. If that fingerprint is already in the workbook, the same receipt doesn't get added twice.

If a workbook was uploaded, it adapts to it

The pipeline inspects the uploaded workbook's existing columns and maps the new receipt onto them — the behavior shown above — instead of forcing its own format on top of yours.

What's in the workbook

A standalone run (no existing workbook uploaded) produces four sheets:

Ringkasan

One row per receipt — merchant, date, subtotal, tax, service charge, discount, and total.

Detail Item

Every line item that was on the receipt — name, quantity, unit price, and line total.

Validasi

The arithmetic check for each receipt — printed total vs. calculated total, and the difference if they don't match.

_receipt_bridge

A hidden sheet that stores each receipt's fingerprint — how duplicate detection and adaptive append actually work behind the scenes.

Three processing modes

Balanced

The default. Extracts what it can confidently read and fills reasonable gaps — good for everyday receipts.

Strict

Only returns fields it's actually confident about, rather than guessing at anything blurry or ambiguous.

Inspect

Returns the raw extraction as JSON instead of a workbook — useful for checking exactly what the model saw before trusting it.

What it doesn't do yet

  • One receipt per submission — batch upload for a stack of receipts at once is planned, not built.
  • No split-bill support yet — it extracts and totals a receipt, it doesn't divide it between people.
  • 10 MB limit on the photo, 15 MB on an uploaded workbook.
  • Best results on itemized receipts with printed totals — a receipt with no visible total to reconcile against still extracts, but skips the arithmetic check.
